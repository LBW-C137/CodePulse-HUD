# 设备卡片跳位修复 — 2026-10-23

## 实际复现

用户报告 0.0.19 中卡片频繁跳位、不遵守 HUD 的稳定分组原则。只读同步捕获
StatusHub 与实际设备 API：同一个 示例项目 B 会话编号保持不变，工作目录却在
示例项目 A 工作目录与 示例项目 B 自身目录间反复切换。工具活动和原生会话
采集的目录信息存在冲突。此前将 file URI 归一为普通路径只能解决同路径表示
差异，无法解决这两个真正不同的目录。

设备排序原来保存了“组的位置”和“会话的位置”，却每次用最新工作目录重新
决定会话属于哪一组，因此一个任务会在两个已存在的组之间往返。状态改变时
相邻卡片被连带挪动，扩大屏幕差分范围。这是表现层的排序缺陷，不是墨水屏
自己把位置画错。

## 修复规则

- 设备专用顺序记录迁移为 version 2，增加会话编号到首次确定项目组的绑定。
  保存的都是哈希编号，不包含原始路径、标题或消息。原有组和会话顺序保留。
- 后续执行目录变化、状态、活动时间、改名不修改绑定；暂时消失后再出现、
  桌面重启也恢复原绑定。未确认项目路径时独立会话仍不会合并为一个任务。
- 继续遵循 HUD：Claude → Codex → Kimi → Grok 的共用 provider 优先级，
  设备支持的仍为 Claude/Codex/Grok；同项目相邻，组内 agent 优先，同级先到
  先得。不按“待确认”排序；重要提醒通过即时刷新与状态标识突出。
- 新增／移除任务、改变筛选或页码、真正新增更高优先级 provider 可按既有规则
  改变布局。此修复不保留空槽，不改变三行及 1/2/3 列规则。
- 绑定只用于设备配置预览和 LAN 设备 API，共用同一个 projector。不改共享
  StatusHub 的执行目录，也不改主桌面/HUD 的数据或样式。显式项目迁移后的
  重新绑定尚未提供 UI；不能把每次工具 cwd 变化都当作用户迁移。

## 验证

54 项两套桌面设备相关回归通过，覆盖实际目录冲突、3/6/9 卡片连续 40 次
变化、历史 v1 迁移、重启、临时消失、混合 provider 优先级、非法绑定和历史
容量清理。主宿主类型检查、构建通过。修复已随唯一统一桌面进程重启上线。

修复前 17:42:04–17:42:49：同一组任务，25 次目录变化，20 次卡片顺序变化。
修复后 17:49:36–17:50:19：同一组任务，12 次目录变化，0 次卡片顺序变化。
两段均没有任务集合增删。证明该真实触发条件已被修复；不是长期所有场景的
外推。设备自动收到新顺序，不需重刷固件。现有旧残影不会因排序修复自行消失。

详细运行采样保存在维护者本机，不随公开仓库发布。
